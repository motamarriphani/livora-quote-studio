# REVIEW — LIVORA Quote Studio Accounts (Convex backend + app.js new sections)

**Date:** 2026-08-10 · **Scope:** `convex/*.ts` (schema, common, company, catalog, quotes, counters) + new app.js sections (library/catalog/history/cloud hooks/AppHooks). cloud.js deliberately skipped per instructions (only grepped for its public API surface to cross-check the saveQuote payload contract).

**Method:** full read of all 6 convex files and app.js (1026 lines); cross-checked index.html `data-action`/`data-tab`/`data-field` values and dynamic ids; verified Convex OCC/serializability semantics against official docs (docs.convex.dev/database/advanced/occ).

## Findings

|---|----------|-----------|-------|---------------|
| 1 | Important | app.js:899-908 (reset) + 790-796 (claimFreshNumber) | **Reset keeps the OLD quoteNo during the async claim.** `reset` clears sections/finalCharge but not `state.quoteNo`, then `claimFreshNumber()` only assigns the new number inside `.then()`. Any `save()` in that window (user types a customer name immediately; debounced cloud sync fires) uploads the new/empty quote **under the previous quote's number**, and `saveQuote` upserts by (company, quoteNo) → **the previous quote in cloud history is silently overwritten/lost**. Additionally `claimNumber().then(...)` has **no `.catch`**: if the claim fails (offline/error) `state.quoteNo` stays the old one permanently and every subsequent sync keeps overwriting the previous quote. | In the reset case (and at the top of `claimFreshNumber`), synchronously set `state.quoteNo = ''` before the async claim; add `.catch(() => { state.quoteNo = autoQuoteNo(); save(); render(); })`; optionally gate `Cloud.markDirty()` until a number is present. |
| 2 | Important | convex/counters.ts:19-21 | **Counter double-claim on first insert per (company, year).** Convex OCC detects conflicts on *shared documents* only — two concurrent mutations that both `query` the (company,year) counter, find nothing, and both `insert` a *new* counter doc (seq=1) do not conflict (different `_id`s, neither in the other's read set) → **both devices receive `LQ-YYYY-001`**. After the doc exists, later claims are safe (same-doc patch → write conflict → auto-retry). The comment "two devices can never receive the same number" is only true after the first claim of each year. | Serialize on a shared doc: store `{seq, year}` on the company doc (every claim patches the same doc → always conflict-detected), or use a deterministic id for the counter doc (`insert(..., { id })` if your Convex version supports custom ids), or catch-and-recheck on insert. |

(Task states last-write-wins is accepted for existing docs — the *double-insert* is the un-accepted part.) | Deterministic quote doc id derived from `companyId + ':' + quoteNo` (custom-id insert), or insert-then-verify-then-merge, or a per-company serialization point. |

## Verified OK

- **Auth gating (no holes found):** all 6 convex functions (`getCatalog`, `saveCatalog`, `listQuotes`, `getQuote`, `saveQuote`, `deleteQuote`, `claimQuoteNumber`, `ensureCompany`) call `requireSubject`. No function trusts a client-supplied `companyId` — every handler derives the tenant from `getCompanyForUser(ctx, subject)`. No cross-company leak found.
- **getQuote/deleteQuote ownership:** both re-fetch the doc and compare `quote.companyId !== company._id` (getQuote returns null, deleteQuote throws) ✓.
- **AppHooks.payload ↔ saveQuote args (task #8):** every arg saveQuote requires is present with the right type (quoteNo/date/timeline strings, customer {name,phone,address} strings, sections array, finalCharge/gst/total/discount/gstAmt/grand/itemCount numbers, validityDays number, terms array-of-strings, spec array, showDims/showSpec booleans). `updatedAt` is **not** in payload but cloud.js injects `payload.updatedAt = Date.now()` (cloud.js:145) before the mutation — contract satisfied.
- **Counter atomicity (existing docs):** once the (company, year) counter doc exists, concurrent claims patch the same doc → Convex OCC detects the write conflict and auto-retries → serializable, no double-issue. Only the first-insert window (Finding #2) is racy.
- **finalCharge reset rule (task #6):** every item-set mutation resets it — addSection (254), addItemFromLib (267), addCustomItem (278), del-section (853), del-item (879), reset (901). toggle-sec, value edits, cloudcatalog, and applyQuote/loadHistoryQuote correctly do NOT reset (snapshot quote keeps its own finalCharge — allowed; cloudcatalog doesn't change the item set).
- **History math (task #7):** renderHistory displays only snapshot fields (`q.grand`, `q.itemCount`, `q.customerName`, `q.date`, `q.quoteNo`) projected by listQuotes — no client recompute, snapshot and itemCount consistent (both written at save time).
- **Delegated click (task #5):** all index.html static `data-action` values match switch cases (add-section, reset, open-catalog, cat-add, cat-save, cat-tab×4, open-history, preview, quote-options, sample, sign-out, close-*, custom-item, download-pdf, back-to-builder); dynamic ones (del-item, del-section, toggle-sec, add-item, cat-edit, cat-del, history-load, history-del) match. `[data-lib]` early-return doesn't shadow any `[data-action]` element (library buttons have only data-lib; nested `.hist-del` button is found by `closest()` before the row's `history-load`). `data-tab` values (services/items/materials/terms) match `catArray()`. All destructive flows use `confirm()` (del-section, sample, reset, history-load, history-del, cat-del). `data-idx`/`data-id`/`data-sec`/`data-item` interpolations are numeric/uid()/Convex-id — safe.
- **Escaping:** `esc()` applied to every user-string rendered into innerHTML (render, renderLibrary names/cats, renderCatTab names/cats/terms/materials, openCatEdit values incl. textarea, renderHistory customerName/quoteNo, renderQuote names/dims/customer/terms/spec). `libTarget` uses textContent. Only the `data-lib` id attribute (Finding #5) is unescaped.
- **Null/undefined (task #4):** catalog-null-before-onboarding is guarded everywhere (renderLibrary/libLookup fall back to LIBRARY; catList returns empty object; reset guards `cat &&`; cloudcatalog guards `if (!cat) return`; getCatalog returns null → `Cloud.catalog` null). `applyQuote` uses `doc.customer?.name` optional chaining ✓. `doc.finalCharge || 0` / `doc.gst || 0` handle 0 correctly. Except for Finding #4, all input-handler lookups guard.
- **Schema ↔ writes:** all fields written by company/catalog/quotes/counters match schema.ts types (companies, catalogs, quotes incl. the 8 totals-snapshot fields, clients incl. nameKey/lastQuotedAt, counters). `sections`/`spec`/`materials` as `v.any()` is the documented flexible-by-design choice.
- **Focus-loss on re-render:** renderSummary skips overwriting `#finalCharge`/`#gst` while focused; addSection re-focuses the new room name; libSearch lives outside `#sections` so library adds don't steal focus.
- **Convex OCC semantics** (docs.convex.dev/database/advanced/occ): mutations are serializable with automatic retry on write conflict — the basis for the "existing-doc upsert / existing counter" safety above.
- **fmt/fmtDate/num coercion:** all totals flow through `num()` before payload, so saveQuote's `v.number()` validators can't reject NaN/undefined.
